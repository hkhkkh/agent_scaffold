> 画布是**模具**，Agent 是**产品**。
> 本平台提供企业级底座（安全沙盒、长期记忆、并发队列、人机审批、执行预算、目标追踪），您在画布上编排出的任意复杂 Agent，既能在平台内实时交互试跑，也能**一键导出为脱离画布、独立运行的完整代码工程包**。

## 二、画布核心交互与布局

界面主要划分为四大区域：

```
┌────────────────────────────────────────────────────────────────────────┐
│  顶部工具栏：名称、新建、打开、撤销/重做、AI 生成、保存、设置、语言、运行按钮 │
├──────────────┬──────────────────────────────────────────┬──────────────┤
│              │                                          │              │
│  左侧面板    │                中间主画布                │   右侧面板   │
│  (组件库)    │              (React Flow)                │  (属性/运行) │
│              │                                          │              │
│  拖拽各类    │  - 节点拖拽放置与移动                    │  - 节点参数  │
│  功能节点    │  - 端口连线 (输入/输出)                  │  - 运行历史  │
│  进入画布    │  - 滚轮缩放 / 控件居中 (Fit View)        │  - 实时时间线│
│              │  - 单节点就地测试 (Run Node)             │  - 输出结果  │
│              │                                          │              │
└──────────────┴──────────────────────────────────────────┴──────────────┘
```

1. **拖拽建图**：从左侧分类列表将节点按需拖入中间网格区域。
2. **端口连线**：鼠标按住节点的输出端口（右侧圆点），拖动引线连接到下游节点的输入端口（左侧圆点）。
3. **节点配置**：单选任意节点，右侧面板自动展示其参数配置项（支持提示词编写、代码编辑、参数微调）。
4. **单节点调试**：在右侧节点属性面板底部，支持单独测试当前节点输入输出，无需从头运行整张大图。

## 三、AI 生成与编辑副驾

AI 不是“一键覆盖画布”的黑盒：会改图的动作默认先给草稿或方案，接受后才写入；
每次 AI 修改都能在版本历史里回看、恢复，也会受公开演示额度约束。公开演示中含
Code 节点的只读工作流只能**查看**历史，不能恢复/回退或保存新版本。唯一的单节点
例外是默认开启的**自动填补**：它只补未设置的参数，仍可撤销。

### 1. AI 生成工作流

顶部「AI 生成」输入目标，生成过程会在对话框里的只读画布上实时显示草稿；关闭
对话框会取消生成，不写入主画布。

- 生成器先改图、再做静态校验；默认还会用 Start 节点的默认值**真实试跑一次**，
  把运行时失败回馈给模型，最多 2 轮；
- 网络、超时、鉴权、限流等外部错误不会触发“删节点”式的自动修复；
- 校验/试跑结果随草稿返回，点「接受」才应用到画布；应用后可 Ctrl+Z 撤销。

公开演示默认关闭自动试跑（`AI_SELF_TEST=false`），生成器也不会提供 Code 节点。

另外，界面默认是「自动」AI 协助：编辑节点描述并停止输入约 **2 秒**后，会自动调用
AI 填补该节点参数。它只写未设置的键或它自己写过、你没改过的键，每次都是普通编辑
（可 Ctrl+Z）；**每次也会占一次公开 AI 请求额度**。想完全手动时，切到「按需」。

### 2. 编辑副驾（右侧 AI 对话）

先在画布上选中要改的区域，再在右侧「AI」对话里描述业务目标。画布上方的阶段栈
会依次显示：**理解 → 研究（可选） → 方案 → 编辑 → 校验 → 试跑 → 产出比对 →
完成**；跳过或失败都会如实显示，不用定时器假装进度。

| | 需要确认（默认） | 放手执行 |
|---|---|---|
| 是否先问 | 先给业务判断卡和修改方案，批准后才改 | 不逐步确认，直接改 |
| 写入范围 | **选区 + 已批准方案点名的节点**；其余只读 | 全画布 |
| 不确定时 | 把假设列出来，等用户确认方向 | 按最合理理解继续，假设写进报告 |
| 安全网 | 快照、校验、试跑、版本记录；**不回滚，只报告** | 同样有；最终校验比原图更差时自动回滚 |

确认模式一轮会发**两次** AI 请求：第一次理解业务并出方案，批准后第二次才执行。
两次都占公开额度，所以访客每天 3 次大约只够一轮“分析 + 批准执行”。

**每一轮新请求都先做业务判断**，不是直接改图：判断卡分开标注目标、成功标准、
用户明确要求、推断、AI 假设和置信度。信息不足时才联网，最多 2 条查询，来源进卡；
公开演示关闭了联网调研（`AI_BUSINESS_RESEARCH=false`），研究阶段会显示为未启用。
网页内容只作为资料，不会被当成指令执行。用户写的 label / description / prompt
不会被无理由改写。

确认模式下，选中的范围会在画布上显示半透明虚线框；方案如果要点名选区外的节点，
会在方案里写出来，批准后这些节点才可写。放手模式改完也会校验、试跑，最终校验
比原图更差时自动回滚；确认模式和试跑失败只报告，不回滚。修改报告和 AI 版本记录
会进入「版本历史」。

侧栏的「执行记录」会逐条列出这一轮实际发生的工具调用、校验、修正、试跑和产出
比对，成功/失败都有标记；思考块按「第 N 轮」编号。画布上方的阶段条只显示当前
阶段，二者一个看进度、一个看审计轨迹。

画布 AI 现在能实际**运行当前草稿并读取结果**：问「跑一下」「测试结果怎么样」
它会调用 `run_workflow` 执行草稿；问「上次为什么失败」会读持久化运行记录
（`get_run_results`）；问「数据库里有什么」会读 `results.db`（`query_database`，
只读）。它也能单独测试一个节点（`test_node`）、看历史版本（`list_versions` /
`get_version`）、看节点坐标（`get_canvas_layout`）、联网搜索（`search_web`），
以及在本地模式下增删改 `results.db`（更新/删除必须带 where 条件，最多 500 行）。
输入框左侧的「图片」按钮可以附最多 4 张截图或照片，模型能直接读图（前端会把
大图缩到 1600px）。试跑结果会出现在右侧「运行」标签的「AI 试跑」卡片里，带
逐节点步骤；它不是持久化运行，所以不会进入运行历史。公开演示里 AI 触发运行
和数据库写入被拒绝，请用 Run 按钮（队列和额度在那里生效）。

画布 AI 使用 DeepSeek 的**原生推理**（`reasoning_content`），洞察/方案轮会流式显示
在回答上方；工具调用轮为了速度和稳定性关闭 thinking。AI 添加的 Code 节点默认
**不勾选「受信任」**，这是刻意的：需要你在右侧面板读代码后手动勾选。放手模式
不会因为等待信任而把整张图回滚——节点会留在画布上，校验会提示哪几个等待勾选。

**副驾现在也知道平台怎么运行**，不只是节点目录：

- 问「现在有定时计划吗 / 下次什么时候跑 / 能跑多久 / 循环怎么用 / 导出后怎么部署」，
  它会读当前设置和这条工作流的计划后回答，不再靠猜；
- 说「把它设成每分钟运行」会让副驾创建一个**暂停的**计划（输入必须匹配 Start），
  然后提示你保存工作流、再明确启用；它不会声称计划已在运行；
- 说「导出后怎么跑」，它会给出 `main.py daemon` 命令（包含间隔、日报时间、输入），
  但不会真的导出或启动；
- 画布目前没有计划管理页面，查看/暂停计划可以直接问副驾，或调用 `/api/schedules`；
- 公开演示模式下创建/启用计划会被拒绝。

### 3. 试跑与产出比对

副驾可以带**样例输入**和**期望产出**：

- 只给样例输入：用样例跑一遍；
- 再给期望产出：试跑后由一次模型调用判断实际产出是否匹配，返回
  `matches / reason / gaps / suggested_fix`；不匹配最多再修一轮；
- 两者都不给：本地默认用 Start 的默认值试跑，只能验证“跑得通”，不能判断业务上是否对；
  公开演示 `AI_SELF_TEST=false` 时不试跑，除非填了期望产出。

试跑是真实调用，可能消耗模型/工具并写结果库，公开演示会计入额度。

### 4. 公开演示下的 AI 限制

公开站点没有账号，额度按“签名访客 Cookie + IP”近似，**不是登录级按人隔离**：

| 限制 | 公开演示值 |
|---|---|
| AI 请求 | 每访客 3 次 / UTC 日；每 IP 10 次 |
| 工作流运行 | 每访客 2 次 / UTC 日；每 IP 20 次 |
| 单次 AI 请求 | 30,000 tokens |
| 每日 tokens | 访客 50,000；IP 200,000；全站 5,000,000 |

- 超限可能是 `429 quota_exceeded`（每日账本/token）或 `429 rate_limited`（每分钟/
  全局窗口），都带 `Retry-After`；流式 AI 在开始后超限会发 `quota_exceeded` 事件。
  请求失败也会占用一次 AI 请求次数；
- 画布运行和节点测试都按一次运行计数；确认模式副驾一轮分析 + 批准执行算两次 AI 请求；
- 顶栏额度是进入页面时的快照，消费后刷新页面才更新；
- 清 Cookie 后仍按 IP 计数，但换 IP 可以重新获得额度；
- Code 节点、自定义工具、调度器在公开模式关闭；「配置 ↔ Python」转换只允许
  admin，生成器提示词不提供 Code；
- 完整部署配置见 [`env/deploy.md`](env/deploy.md) §1.1。

### 5. AI 修复（画布问题面板）

画布问题面板的「AI 修复」**打开对话框就会自动发起一次修复**，所以打开本身会消耗
一次公开 AI 请求；反复开关或切换「同时修复警告」都会再发请求。

- 默认只修 blocking `error`；勾选「同时修复警告」会把 warning 也发给模型；
- 结果先给 diff：被删节点用红色 callout 单独列出，方便判断模型是不是“删光就没错”；
- 可以在底部输入一句额外指令再点「重试」；
- 只有点「应用」才替换画布（可 Ctrl+Z 撤销）；点取消不改变画布。

## 四、节点系统与常用能力矩阵

平台内置 16 种企业级节点，按核心职责分类：

### 1. 输入与输出
- **开始 (Start)**：工作流唯一入口，定义外部调用该 Agent 时接收的参数字典（JSON Schema）。
- **结束 (End)**：工作流终点，收集并返回该 Agent 的最终交付成果（可指定输出键名、携带完整运行变量）。

### 2. 核心大模型与智能体
- **智能体 (Agent)**：具备 **ReAct 循环自主推理**能力，模型自主判断是否调用、调用哪个已注册的业务工具，直至得出最终结论。
- **大模型 (LLM)**：执行单次提示词对话或文本生成，支持 Temperature、模型指定、输出 JSON 模式约束。
- **主管 (Supervisor)**：多智能体协作调度枢纽，动态将请求分派给不同专长的子节点。

### 3. 工程底座与业务扩展
- **代码 (Code)**：在严格资源受限的 Python 沙盒中执行脚本，处理数据清洗、特征提取、数学计算。需在面板勾选“已信任 (Trusted)”。
- **工具 (Tool)**：直接显式调用注册在案的单一业务工具（如天气查询、内部订单查询、系统 API），不消耗模型推理轮数。
- **长期记忆 (Memory)**：支持跨越单次会话的语义/文本知识库。
  - `search` 模式：按语义或关键词召回历史经验；
  - `write` 模式：将本次运行提炼的最佳模式持久化存储。
- **目标追踪 (Goal)**：管理长时间多步骤任务。支持 `start` 初始化步骤清单、`advance` 推进进度、`show` 查看当前阶段。

### 4. 逻辑控制与人机协同
- **条件分支 (Condition)**：按表达式自上而下匹配。命中分支则引流到对应连线，支持默认 fallback 分支。
- **变量汇总 (Aggregator)**：将多路互斥或并发分支的数据聚合为单一输入，送给下游节点。
- **循环 (Loop)**：设置执行上限（`max_iterations`）与退出条件，安全迭代处理列表或逐步求精。
- **人工确认 (Human Input)**：**企业级安全生命线**。当遇到高危操作时挂起流程，仅通过前端确认对话框提交到 `POST /runs/{id}/resume` 后恢复（**没有**基于外部 Webhook 的审批/恢复通道）。

## 五、核心数据流动机制（变量与模板）

所有节点都在读写一份由运行时托管的共享状态 `vars`。后置节点可以通过双大括号 `{{ }}` 语法灵活引用上游节点的数据：

### 1. 常用引用占位符

| 语法 | 含义 | 示例 |
|---|---|---|
| `{{ vars.<node_id>.out }}` | 引用指定节点的默认输出 | `{{ vars.agent_audit.out }}` |
| `{{ vars.<node_id>.out.field }}` | 引用指定节点输出 JSON 中的子字段 | `{{ vars.ast_analyze.out.risk_score }}` |
| `{{ inputs.in }}` | 引用直接连入本节点当前输入端口的数据 | `{{ inputs.in }}` |
| `{{ <param_name> }}` | 引用 Start 节点中声明的全局输入参数 | `{{ system_name }}` 或 `{{ code_snippet }}` |

## 六、实战案例：自主代码安全审计与重构智能体

平台已内建标杆工作流：**`wf-security-remediation-expert`**。该案例展示了 12 个高阶节点如何紧密配合，实现全流程闭环：

```
[Start: 接收代码] ──► [Memory: 检索历史规范] ──► [Goal: 规划5步审计目标]
                                                          │
┌─────────────────────────────────────────────────────────┘
▼
[Code: AST规则特征提取与打分] ──► [Agent: 智能体多工具综合研判 CWE-89]
                                           │
┌──────────────────────────────────────────┘
▼
[Condition: 风险分支决策]
  ├─► (风险分 >= 80) ──► [Human Input: 触发人工审批] ──┐
  └─► (低危自动通过) ──────────────────────────────────┼─► [Aggregator: 分支汇合]
                                                       │
┌──────────────────────────────────────────────────────┘
▼
[LLM: 生成参数化重构代码] ──► [Memory: 修复模式自沉淀入库]
                                      │
┌─────────────────────────────────────┘
▼
[Goal: 推进标记目标完成] ──► [End: 交付全流程综合报告]
```

### 运行该案例的步骤：
1. 点击顶部 **「打开已保存的工作流」** 图标。
2. 在弹出列表中选中 **「自主代码安全审计与重构智能体」**。
3. 点击画布**左下角**的 **Fit View** 控件（React Flow 默认控件），画布节点居中排列。
4. 点击顶部 **「运行」** 按钮，系统弹出参数输入框，已预填包含 SQL 注入特征的测试代码。
5. 点击弹窗内的 **「运行」**，右侧时间线面板将实时显示节点执行步骤与耗时。

## 七、人机协同确认（Human-in-the-Loop）

当工作流执行到带有风险的操作节点时（例如本案例中识别出漏洞且风险分达到 90 分）：

1. **自动阻断挂起**：后端生成挂起快照（Checkpoint），工作流状态进入 `interrupted`。
2. **前端弹出审批框**：界面中央自动弹出「需要确认」对话框，显示：
   - 智能体提炼的漏洞定性结论与风险分析；
   - 待确认的具体操作建议；
   - 「拒绝」与「通过」操作按钮。
3. **确认恢复**：
   - 管理员点击 **「通过」**，前端将签署信息回传至 `/runs/{id}/resume`；
   - 工作流自动从暂停的检查点精准恢复，继续往下执行方案重构与入库。

## 八、Agent 独立导出与部署（M4 交付物）

编排调试完成的 Agent 可以完全脱离本平台独立交付和部署。

### 1. 触发一键导出

向后端 API 发送导出请求（**当前前端画布没有导出按钮** —— 导出只能走 API / CLI）：
```bash
curl -X POST http://127.0.0.1:8001/api/workflows/wf-security-remediation-expert/export-agent
```
导出的完整独立项目将生成于：`data/exports/wf-security-remediation-expert/`。

### 2. 导出包的目录结构

```text
├── agent.yaml            # 工作流结构定义（逻辑采用 !ref 外置引用）
├── manifest.yml          # 沙盒、工具依赖与凭据清单
├── agent.lock            # 运行时防篡改 SHA256 封签与版本锁定
├── main.py               # 独立启动入口（run / daemon / serve / selfcheck）
├── requirements.txt      # 锁定精确 Hash 的第三方依赖清单
├── Dockerfile            # 生产级两阶段容器镜像构建文件
├── code/                 # 外置出的 Python 逻辑代码文件（IDE 友好）
├── prompts/              # 外置出的大模型提示词 Markdown 模板
├── tools/                # 该 Agent 独占的业务工具实现（多 Agent 严格隔离）
└── vendor/runtime/       # 纯净的 Agent 执行引擎（经 AST 校验无平台数据库依赖）
```

### 3. 独立运行命令

进入导出的目录，无需启动任何画布或数据库即可直接运行：

```bash
# 1. 完整性自检（校验代码、运行时与提示词是否被未经授权篡改）
python main.py selfcheck
# 输出: RESULT=PASS (0 problems)

# 2. 单次命令行执行并输出 JSON 结果
python main.py run --input '{"code_snippet": "SELECT ...", "system_name": "Demo"}'

# 3. 管道模式（标准 JSON Lines 交互）
python main.py serve

# 4. 持续运行：每 60 秒一个有界周期 + 每天 08:00 日报
python main.py daemon --interval 60 \
  --input '{"line_id": "IM-07", "mode": "monitor"}' \
  --daily-at 08:00 --timezone Asia/Shanghai \
  --daily-input '{"line_id": "IM-07", "mode": "daily_report"}'
```

`daemon` 是导出包自带的调度层，不依赖画布或平台：

- 每个周期是**一次有界运行**，失败只记这一条，下一分钟照常跑；
- 日报按本地日期最多一次，跨进程重启不会重复发送；
- `data/agent_cycles.db` 记录每周期状态/耗时/错误，`data/health.json` 给看门狗，
  `data/agent.log` 为 JSONL（10 MB 轮转），`data/results.db` 是工作流自己写的数据；
- 周期日志默认保留 365 天（`--retain-days`），`results.db` 不自动清理；
- 同一数据目录只允许一个 daemon（文件锁），避免重复写产线参数；
- 进程本身由 systemd / Docker / Windows 计划任务负责重启——**daemon 管周期失败，
  守护进程管进程死亡**。

导出包 README 里带 systemd 单元示例。换业务时只需换 `--input` / `--daily-input` /
间隔 / 时间，工作流与自愈规则仍由该业务自己的图决定。

### 4. 容器化部署

如果机器装有 Docker，可直接将 Agent 构建为不可变容器镜像：
```bash
docker build -t my-security-agent:v1 .
docker run --rm my-security-agent:v1 selfcheck
```

## 九、常见问题与操作排查

### Q1: 运行后发现步骤停留在某一步转圈？
- **排查**：检查工作流中是否包含 `human_input` 节点。若命中阻断，界面会弹出审核对话框，需人工点击「通过」或「拒绝」流程才会继续。
- **机制**：前端具备断流主动对齐（syncRun）机制，若意外关闭弹窗，可在右侧面板点击「清除」后重新触发。

### Q2: 自定义 Python 代码节点报错？
- **排查**：请确保在节点属性面板中勾选了 **「已信任 (Trusted)」**。平台出于安全防护策略，默认禁止执行不可信的脚本。

### Q3: 运行结果保存在哪里？
1. **磁盘文件**：每轮运行落盘于 `data/runs/<run_id>.json`。
2. **数据库记录**：元数据持久化保存在 `data/scaffold.db`。

### Q4: AI 提示 `429 quota_exceeded` 怎么办？
公开演示的匿名额度用完了。AI 请求按访客 3 次/UTC 日、IP 10 次/UTC 日；运行按
访客 2 次、IP 20 次。额度在 UTC 零点重置；清 Cookie 不会绕过 IP 账本。具体值和
排查见 [`env/deploy.md`](env/deploy.md) §1.1。

### Q5: 为什么公开站生成后没有自动试跑？
公开 `.env.public` 默认 `AI_SELF_TEST=false`，避免一次生成消耗两次模型调用。
本地默认开启。副驾如果填写了「期望产出」，为了做产出比对仍会试跑一次。
3. **前端查看**：在右侧「运行」面板底部展开「输出 (Outputs)」即可查阅与一键复制。

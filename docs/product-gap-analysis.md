# Agent Scaffold 体验复盘与商业化落地差距剖析

> **核心警醒**：
> “如果给客户这样的产品，一分钱也拿不到。”
> 本文档基于 2026-10-09 用户在画布上亲自搭建真实业务 Agent（“电商自主售后与调研 Agent”）时的实际体感与操作痛点，进行直面问题的严肃复盘，彻底剖析为什么“底层测试全绿，但拿给客户却毫无商业价值”，并给出商业化必须落实的改造清单。

> **本文件是 2026-10-09 的复盘快照，不是现状。** 当时体感里的若干问题（成果被埋进 JSON、

## 一、四个真实痛点（2026-10-09 实况）

用户希望在画布上构建的不是一段死的代码脚本，而是一个**“活的、能像普通商业产品一样交互的 Agent”**：
能联网调研（遇到商品纠纷/行业标准时自主查证并拿出证据）、能与人交互（缺订单号/商品图时停下追问，
拿到回答再继续）、能反复思考（方案不成熟时自我批判，打回循环节点再优化）、
最终能一眼看见方案（像人类客服/咨询专家那样，给出排版清晰、有理有据的结论）。当时拿到的却是：

| 用户期待 | 当时的实况 | 病因 | 致命后果 |
|---|---|---|---|
| **直观的交互与方案交付**，跑完直接给出图文并茂的方案 | 方案被塞在第 10 层的某个变量字典里，右侧只有毫秒数、状态码、折叠的 JSON 树 | 右侧「运行」面板是按**后端工程师查日志 / 看 Trace / 排查堆栈**的逻辑设计的，把调试面板当成了交付界面 | 客户看不懂，以为 Agent 根本没生成方案 |
| **真实的人机参与感**，缺订单号就停下弹窗追问，打字补充后恢复 | 弹窗时常卡死或逻辑被绕开；弹出的像程序员填表单，缺乏对话感 | `interrupt()` 挂起与快照恢复底层硬核，但产品层未把「提问」包装成对话卡片；SSE 断流重连缺陷让前端卡在 loading | 客户感觉“这就是个死板的代码管道，不是懂交流的智能体” |
| **网状拓扑、智能分流**，按意图自动分发到不同专家 | 动态多端口连线频繁报错，退化成单向线性流水线 | 前端只支持静态端口，而 `Condition` 节点会按 `branches` 动态生成多个分支 Handle（`Loop` 的 `continue/done` 是静态的，不在此列） | 客户无法设计真正的网状图，退化成只能走单线 |
| **感知 Agent 的思考与联网**，实时看到“正在搜索…”“进入第二轮反思…” | 界面只有 step 1/2/3 的数字跳动，看不见它联网查了什么、思考了什么 | 思考片段与 `http_request` 工具调用痕迹全被塞进 `node_output_chunk` 后台事件，UI 只渲染一个绿勾和耗时 | 缺乏可信度，感觉不到“自主性” |

**一句话**：对话、方案、联网、思考这些「智能感」，当时都没有产品层的透出面。

## 二、商业化交付必须落地的整改方案

为了让客户坐在这个画布面前，能像普通人使用真正成熟的 Agent 产品一样顺畅，必须在交互层和产品层完成以下重构：

```
┌─────────────────────────────────────────────────────────────────────────┐
│                       【新版交付型运行面板】                            │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  🎯 最终解决方案（高亮置顶，Markdown 优美排版，一键复制 / 导出报告）    │
│  ┌───────────────────────────────────────────────────────────────────┐  │
│  │ 针对您扫地机器人闪红灯且商家拒保的问题，我们已为您完成事实核实与法规 │  │
│  │ 调取，解决方案如下：                                             │  │
│  │ 1. 维权结论：属于出厂硬件缺陷，在三包法第 9 条范围内强制换新...  │  │
│  │ 2. 向平台申诉的话术模板...                                       │  │
│  └───────────────────────────────────────────────────────────────────┘  │
│                                                                         │
│  🧠 智能体动态思考与行动轨迹（展开式 Timeline）                         │
│  ├─ 🌐 [联网检索] 已查阅：《消保法三包规定》、《某平台售后争议处理标准》│
│  ├─ ⚠️ [人机确认] 发现缺少订单号，已向用户完成追问并获得补充...         │
│  └─ 🔄 [反思迭代] 首轮方案自评置信度 0.65，触发第 2 轮反思深入检索补充 │
│                                                                         │
│  ⚙️ 调试详情（收起至底部折叠框，供专业开发者选看，默认不打扰客户）       │
└─────────────────────────────────────────────────────────────────────────┘
```

### 1. 交付物体验升级：置顶 Markdown 富文本方案
- **改动**：在右侧面板顶部设立 **「最终方案交付区」**。如果工作流包含文本方案输出，直接进行优美的 Markdown 渲染，字体加大、段落清晰，并提供「复制文本」和「导出为 PDF/Markdown」。
- **效果**：客户运行结束的第一眼，看到的是**有价值的商业方案**，而不是一堆代码日志。

### 2. 交互式追问体验：原生对话式交互卡片
- **改动**：当命中 `Human Input` 追问节点时，界面正中央弹出的不再是冰冷的“参数审批框”，而是**“智能体沟通卡片”**：
  - “智能体正在为您制定方案，但需要您提供：【订单号或故障照片】”；
  - 提供单行输入框与上传控件，用户按回车发送，流程继续流转。
- **效果**：用户真正参与到 Agent 的推理回路中，体验人机协同。

### 3. 动态思考与联网动作的可视化透出
- **改动**：在节点流转列表中，将 Agent 的思考片段（`thought`）和工具调用（`http_request` 查到了什么）作为可折叠的小标签展示。
- **效果**：客户能清晰看到 Agent 的“智商”，清楚知道它真的去联网了、真的经历了第 1 轮到第 2 轮的反复自我修正。

### 4. 彻底消除动态端口的前端断层
- **改动**：前端在解析图结构时，自动根据节点的配置同步计算出所有动态输出 Handle（`yes/no`、`branches`、`continue/done`），确保多分支网状图在画布上拖拽连线时 100% 顺滑，不出现报错悬空。

## 三、结语

一个能卖得出去的 Agent 产品，其价值公式是：

$$\text{商业价值} = \text{底座工程能力（安全/并发/隔离）} \times \text{对客交互体验（看得懂/能参与/拿得到方案）}$$

过去我们在前半段投入了 90% 的精力，把安全、AST、沙盒、哈希封条打磨到了极致；但后半段的缺失，直接让整个乘积趋近于零。

**这份文档不仅是一次体感复盘，更是产品从“自嗨脚手架”向“真正商业化交付”蜕变的军令状。**

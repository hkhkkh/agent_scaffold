# 国际化（中英切换）

## 1. 架构决策：本地化在后端出口完成，不在前端

**理由**：节点名、参数说明、端口名全部来自后端目录。
若在前端做映射，就要维护一份会漂移的翻译表；在后端做，
前端通用渲染**一行都不用改**（它读的始终是 `label`）。

```
schema.py 的 label_zh / description_zh
        │
        ▼  localize(value, lang)   ← 递归替换 + 剥掉所有 _zh 字段
   /api/node-types?lang=zh
        │
        ▼
   前端照常渲染（不知道语言存在）
```

**空值回退英文**，因此可以逐步翻译，不会出现空白标签。

`localize()` 只替换 `LOCALIZABLE_KEYS` 里的键（`label` / `description` / `message`）。
**不在列表里的字符串任何语言下都保持英文 —— 这是故意的**：
有些字符串是*数据*不是界面文案（Condition 分支名、发给模型看的 JSON Schema）。

`normalize_language` 认 `zh`、`zh-CN`、`zh-Hans`、`zh_TW`，
不认识的一律回退 `en`（**不抛异常**）。

## 2. 后端改哪些文件

| 位置 | 内容 |
|---|---|
| `graph/schema.py` | `SUPPORTED_LANGUAGES`、`normalize_language()`、`localize()`、`LOCALIZABLE_KEYS` |
| 带 `_zh` 字段的类型 | `InputPort` `OutputPort` `_ParamBase` `SelectOption` `NodeTypeSpec` `ValidationIssue` |
| `api/catalogue.py` | `/node-types` `/tools` `/state-fields` 均接受 `?lang=` |
| `api/workflows.py` | `/workflows/validate?lang=` 也本地化（**原先遗漏，是坑 1**） |
| `graph/validate.py` | **26 条**校验消息全部双语（28 个调用点） |
| `tools/registry.py` | `ToolDef.label_zh` / `description_zh` |
| `nodes/*.py` | 全部节点翻译（节点类型数归 [`../reference/backend-layers.md`](../reference/backend-layers.md) §2） |
| `runtime/sandbox.py` | `CODE_CONTRACT_HELP_ZH`（Code 节点的契约说明） |
| `backend/scripts/check_i18n.py` | 校验脚本（`-m scripts.check_i18n`，在 `backend/` 下跑） |

### [重要] 给模型看的文本**永远是英文**

`ToolDef.description_zh` **只用于界面**。`openai_schema()` 始终发英文 `description`。

**原因**：那是模型读的内容。如果连它一起翻译，
**把界面切成中文就会悄悄改变 agent 选择哪些工具** —— 语言设置不该有这样的副作用。

同一条原则也适用于 `repair-graph` 喂给模型的 issues。

## 3. 前端改哪些文件

**`src/i18n/translations.ts`**：

- `MessageKey` 从**英文表推导**（`keyof typeof en`）
- 中文表声明为 `Record<MessageKey, string>`
- ⇒ **漏翻译是 TypeScript 编译错误**，不是运行时空标签

**`src/i18n/index.ts`**：

- `useT()` —— 组件用，订阅语言变化，自动重渲染
- `translate()` —— store / 事件处理器用（**不能**在非组件里调 hook）
- 语言持久化在 `localStorage['scaffold.locale']`
- 首次访问按 `navigator.languages` 判断

**`src/App.tsx`**：

- 切换语言 → effect 依赖 `locale`，自动重新拉取后端目录
- **同时要重新调 `validate()`**（见坑 3）

已接入全部 13 个组件。顶栏语言按钮显示的是**点了会切到的语言**
（显示 `English` 表示当前是中文）。

---

## 4. 三个坑与 `check_i18n.py` 的检查

校验消息是**运行时拼出来的句子**，不是静态目录条目，所以比节点翻译多三个坑
（接口漏 `localize()` / 消息里内嵌的目录标签 / 切语言不重校验），
外加 `check_i18n.py` 检查的五件事（含那个让守卫静默失效的 raw-string 陷阱）。

→ 坑的症状、根因与修法全部归 [`../lessons/i18n.md`](../lessons/i18n.md) §1–§4 与 §检查清单。

# i18n 的坑

> i18n 的整体设计 → [`../current/i18n.md`](../current/i18n.md)
> 本文件是**坑与教训**。

---

<a id="i1"></a>

## 1. [重要] 接口漏了 `localize()`

### 症状

目录接口（`/node-types` / `/tools` / `/state-fields`）都本地化了，
但**中文界面里校验提示是英文**。

### 根因

`/workflows/validate` 直接 `return validate_graph(graph)`,
**没有过 `localize()`**。

### 修法

照 `catalogue.py` 的模式：

```python
localize(report.model_dump(mode="json"), lang)
```

### 推广

**加了新的「返回后端生成的文本」的接口时，记得挂 `localize()`。**

静态目录有 `loadCatalogue()` 兜着，**动态生成的内容没人管**。

<a id="i2"></a>

## 2. [重要] 消息里内嵌的目录标签也要跟着翻译

### 症状

```
「LLM」的参数「Prompt」需要填一个值。
```

参数名 `Prompt` 是**目录里的英文标签**，而界面上那个输入框写的是「提示词」。

### 为什么这比不翻译更糟

**指向一个屏幕上不存在的名字** —— 用户会去找一个叫「Prompt」的字段，
而屏幕上只有「提示词」。

### 修法

凡是把 `param.label` / `port.label` 拼进 `*_zh` 消息的地方，
一律走 `validate.py` 的 `_zh_label(obj)`。

### [重要] 例外：**用户自己写的节点名不走**

那是**用户的话**，用什么语言写的就原样引用。

**这个区分很关键** —— 它意味着「不要 blindly 翻译所有嵌入的字符串」。

<a id="i3"></a>

## 3. [重要] 切语言不会自动重校验

### 症状

界面全变英文了，**顶栏那个红色校验徽章还写着中文**。

### 根因

消息是**后端按语言生成**的，但 `issues` 存在**前端 store** 里。

`App.tsx` 原来的 effect 只依赖 `locale` 重新拉**目录** ——
没有人负责刷新校验结果。

### 修法

把 `validate()` 也加进那个 effect。

### [重要] 推广（这条最重要）

> **任何由后端按语言生成的运行时文本，切语言时都必须重新请求。**

静态目录有 `loadCatalogue()` 兜着，**动态生成的内容没人管**。

新增这类接口时，记得**同时挂进切语言的 effect**。

<a id="i4"></a>

## 4. [最重要] Python 原始字符串里 `\u300c` **不是**转义符

### 症状

守卫**静默失效** —— `check_i18n` 全绿，但**其实什么都没查**。

### 根因

```python
re.findall(r"\u300c([^\u300d]+)\u300d", text)   # ← 错，永远匹配不到
```

`r"..."` 里 `\u300c` 就是 **6 个字面字符**，不是「」。

**这个正则是为了检查「中文消息里不出现英文目录标签」而写的 ——
而它从来没能匹配到任何东西。**

### 修法

```python
re.findall("\u300c([^\u300d]+)\u300d", text)    # ← 对
```

### 教训

> **守卫写完一定要反向验证** —— 故意制造一个它该抓的错误，
> 确认真的报 FAIL。
>
> **否则你只是多了一个永远绿的装饰品。**

→ [`process.md`](process.md) §反向验证

## 5. `_zh` 字段漏到客户端

`localize()` 只替换 `LOCALIZABLE_KEYS` 里的键
（`label` / `description` / `message`），**并且剥掉所有 `_zh` 字段**。

不剥的话 payload 体积**翻倍**，而且前端会看到两套字段。

`check_i18n.py` 有一条专门校验这个。

---

<a id="i6"></a>

## 6. 给模型看的文本**永远不能翻译**

原则与它的两个位置（`ToolDef.description_zh` 只用于界面、`repair-graph` 喂给模型的
issues 永远英文）归 [`../current/i18n.md`](../current/i18n.md) §2 ——
原则归 `current/`，这里只留指针。

---

## `check_i18n.py` 检查的五件事

1. **切语言时标识符不变** —— 否则一种语言存的工作流在另一种语言下打不开
   （**这是最容易犯的错**）
2. `_zh` 字段不外泄到客户端
3. 缺翻译时回退英文，而不是变空
4. **26 条校验规则全都带中文**（**AST 静态扫描**，不依赖样例图能否触发）
5. **中文消息里不出现英文目录标签**

第 4、5 两项**已做过反向验证**：临时删掉一条中文 /
把 `_zh_label` 改回 `param.label`，脚本都正确报 FAIL 并指出具体行号。
